# gallery3d · 复盘与踩坑记录（2026-10-07）

给接手 agent 的避坑手册。每条含：现象 → 根因 → 解法 → 教训。

---

## A. 环境与工程类

### P0 非交互 shell 找不到 npm
- 现象：agent 终端 `npm: command not found`，交互终端却正常。
- 根因：Node 是官方 tar 包解压到 `~/.local/node`，PATH 只写进了 `~/.zshrc`；非交互 shell 不加载它。
- 解法：所有自动化命令前缀 `export PATH="$HOME/.local/node/bin:$PATH"`。
- 教训：交接必须写明运行时真实安装位置与 PATH 注入方式，不能假设"机器上有 node"。

### P1 依赖版本冲突警告
- 现象：`npm ls` 报 drei 的传递依赖 stats-gl peer 要求 three@0.170，项目是 0.186。
- 解法：实测运行无异常（stats-gl 非核心路径），接受警告，**不降级 three**。
- 教训：peer 警告先验证运行路径再决定是否处理；为警告降级主依赖会引入更大风险。

### P2 HEIC 素材
- 现象：177 张源片含 6 张 HEIC，浏览器纹理链路不能直接吃。
- 解法：素材管线用 macOS 自带 `sips` 统一转 JPEG（长边 2048、质量 88），零第三方依赖。
- 注意：脚本仅 macOS 可用；换平台需替换为 sharp/ImageMagick。

## B. 渲染与画面类

### P3 黑盒严重欠曝、作品不可见
- 现象：初版墙面近全黑，只有画框轮廓。
- 根因：MeshStandardMaterial 对 ambient 响应弱；初版环境光 0.15、墙色 #1b222b 过暗。
- 解法：环境光提到 0.55 + 半球 0.5 + 空间点光（decay 1.6、distance 30）+ 墙色 #384657 + 曝光 1.15；作品加贴图自发光 0.22 保底。
- 教训：黑盒不等于零照度。冷调影调靠"灰蓝阶墙面 + 受控光斑"，不是把灯全关小。调光是多参数联动，单拧一个滑块会反复横跳。

### P4 地面出现突兀锥形高光
- 现象：画前地面有一束白色光锥，像探照灯。
- 根因：地面 metalness 0.3 / roughness 0.34，厅顶点光在高反射地面形成高光。
- 解法：地面降 metalness 0.1、提 roughness 0.62（暗廊 0.08/0.7）。
- 教训：室内哑光地坪别用金属感参数；Standard 材质的反射观感要在灯光定型后再收。

### P5 每幅一盏真射灯不可持续
- 决策：177 幅 × SpotLight 会直接击穿光源预算和阴影成本。
- 解法：每画一张椭圆径向渐变 CanvasTexture 面片贴墙做"洗墙光斑"（零光源），灯轨/灯头保留为哑黑装饰几何，光感由假光斑+自发光表达。
- 教训：风格化照明优先用"画出来的光"，真光源只给空间整体打底。

## C. 相机与交互类（本项目最大坑区）

### P6 相机莫名带 roll，画面倾斜
- 现象：intro 过后画面歪了近 55°，调 yaw/pitch 怎么都正不回来；实测相机初始 rotation 为 (x:-0.96, y:1.54, z:0.96)、order=XYZ。
- 根因：相机在挂载前已带非零欧拉角，且默认 XYZ 欧拉序下 yaw/pitch 会串出 z；只改 x/y 不改 z，roll 永远残留。
- 解法：挂载即 `rotation.order='YXZ'`；**每帧 `rotation.set(pitch, yaw, 0)` 强制 z=0**，姿态只有 Player 一个写入口。
- 教训：第一人称相机必须锁定 YXZ 且把 roll 当敌人；怀疑姿态时先把完整 rotation 三元组打印出来，别凭感觉调。

### P7 自研 AABB 碰撞对角卡死
- 现象：斜着蹭墙走，分轴推进时 x/z 双轴同时归零，人钉在墙上。
- 根因：AABB 分轴推出无法表达沿墙滑动；对角接触时两轴互锁。
- 解法：换 three 官方 `Octree + Capsule`，碰撞后沿命中法线推出并去掉法向速度分量，自然滑动。
- 教训：角色碰撞不要手搓；官方例子（webgl_games_octree）已经把滑动/封顶/门洞处理好。渲染建墙与碰撞体必须同源（wallBoxes → Octree）。

### P8 点击作品无反应（真实事件也不触发）
- 现象：真实鼠标点画心，R3F onClick 不执行。
- 根因：onClick 挂在"画框 mesh"上，但射线先命中前方的"作品平面/卡纸 mesh"（同 group 兄弟节点）。**R3F 事件只在命中对象及其祖先链冒泡，不会到兄弟节点**，画框永远收不到。
- 解法：把 onClick/onPointerOver/Out 上提到包裹整幅作品的 **group**。
- 教训：R3F 交互事件一律挂最小公共祖先 group；贴多层贴片（框/卡纸/画/光斑）时尤其注意。

### P9 JS 合成事件"假测试"误导
- 现象：dispatchEvent(new PointerEvent(...)) 后 onClick 不触发，一度误判功能有 bug。
- 根因：R3F 靠自己 raycast + 指针命中系统驱动，手工合成事件没有命中拓扑，喂不进它的事件状态机。
- 解法：交互验证用真实浏览器点击（CDP/browser_use）；程序化验证加 QA 入口 `?focus=n` 直接驱动状态。
- 教训：测 3D 交互，合成 DOM 事件不算数；要么真指针，要么在状态层开测试入口。

### P10 帧率 41 以为是性能事故
- 现象：画面静止只有 40-41fps，标准档/perf 档几乎一样。
- 根因：自动化浏览器宿主显示被节流到 42Hz；空页面裸 rAF 也是 42Hz。M1 Metal 真实后端、drawcall 130，无渲染瓶颈证据。
- 解法：测帧率前先量 rAF 原生节拍做基线；真机 60Hz 终验列专项任务。
- 教训：性能数据先证伪测量环境；dpr/AA 变化对帧数无影响时，瓶颈大概率不在 GPU。

### P11 PointerLock 体验不适配本项目
- 决策：黑盒观展要"随时可点 UI、随时退出"，PointerLock 锁定光标后点击大图/按钮体验割裂。
- 解法：弃用 PointerLock，改自持 yaw/pitch：左键按住拖拽环视（阈值 7px 区分点击/拖拽）+ 光标在屏上的位置提供 ±6°/±4° 微转。
- 教训：交互选型服从使用场景，别默认 FPS 那套；点击作品与拖拽环视共用一键，必须有 moved 阈值仲裁。

## D. 数据与布局类

### P12 挂位数量随门位漂移
- 现象：各端墙因门位置不同算出 7/8 不等，布展索引错位。
- 解法：端墙改对称居中排布（`END_WALL_START`），每扇门恰好占 1 位，锁定 48 位/厅、总 192。
- 教训：布展索引需要稳定容量契约（SLOTS_PER_HALL=48），容量不能由几何偶然决定；用单测钉死。

### P13 布局多份拷贝不一致
- 风险：平面图、建墙、碰撞各写一份坐标迟早漂移。
- 解法：`domain/gallery.ts` 唯一真源；平面图由 `gen-floorplan.mjs` 生成，建墙/碰撞/挂位/小地图全部 import 同一常量。
- 教训：空间坐标单一数据源 + 生成产物（SVG/纹理）不手改。

## E. 交付与验收类

### P14 内嵌预览建不了 WebGL
- 现象：IDE/agent 内嵌预览报 "Could not create a WebGL context"（SwiftShader/沙箱）。
- 解法：`open http://localhost:5173` 用系统 Chrome（M1 Metal）验收；勿在沙箱窗里判断应用好坏。
- 教训：3D 项目的"打不开"先分清楚是应用挂了还是容器不支持 WebGL（看 renderer 字符串：SwiftShader=软件，Apple GPU=硬件）。

### P15 dev server 跨会话失联
- 现象：上一会话起的服务，HTTP 200 但预览通道断开，用户访问不到。
- 解法：杀掉旧 PID，用 web_server 类型重起并 OpenPreview + `open` 双保险。
- 教训：交接时确认服务进程归属与访问方式；长期交付应提供 `npm run preview` + dist 静态包，不依赖某人的 dev server。

## 通用经验沉淀

1. **先跑通再做漂亮**：领域模型 + 单测先行（18 钉），3D 层只消费纯函数，后期改布局成本极低。
2. **调不动时加观测**：相机姿态、命中计数、落点坐标、rAF 节拍——插桩一次比重启猜测十次快；验完即删。
3. **验收环境三要素**：真 GPU、真指针、真刷新率。任一为假，结论都要打折。
4. **风格化渲染的成本顺序**：自发光/假面片 < 少量点光打底 < SpotLight/阴影；预算从便宜端开始花。
5. **QA 入口是资产**：`?artview / ?focus / ?fps / ?quality` 让每个场景秒达，回归成本从分钟级降到秒级，后续功能继续沿用此模式。
6. **旧文档会说谎**：决策被实战推翻后，必须在交接文件留"覆盖表"，否则下一个 agent 会按 ADR-0003 重新手搓 AABB。
